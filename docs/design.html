00现状：v1.0 已发布

2026 年 10 月 6 日发布 1.0.0，第一个能在线更新的版本。本页原是开工前的计划书（v0.2）；下面各节保留当时的思路，并标出实际做成了什么、哪些改了主意。完整的现状以 README 和各篇文档为准。

Mosaico、iOS App、骑行导航还没开始以后

和计划不一样的地方

  • 代理：没走局域网代理，直接在板子上跑 Shadowsocks，只代理需要的域名，TLS 证书照常端到端校验。
  • 国内大脑：没自建服务器、没让用户填 API key，直接用小智官方服务器和它的激活码绑定，零配置。小智协议客户端写在 Boopie 组件里，不用合并两套固件，IDF 版本问题也就没有了。
  • 密钥：token 存在 NVS，用户自己填；考虑到要能反复刷机，没开 NVS 加密，丢了板子就去官网吊销 token。
  • Muse 回复：官方服务对板子只返回文字（output_modality 为 text），所以回复以字幕形式显示。
  • 主界面：从“多应用系统”收敛成“宠物为主”：四向界面，左边设置、右边应用、上面小窝（小世界）。

01项目概述

Meta 在 2026 年 10 月 2 日开源了 Muse Gadgets：一套 ESP32 固件和 Linux SDK，让现成的开发板变成 Muse 的外设。Boopie 以这套固件为起点，扩展成一个通用的圆屏小系统。

核心定位

  • Muse 是一个应用，不是全部。它常驻在系统里，按键就能对话；其他时间屏幕交给宠物、表盘和各类小应用。
  • 一套像素画风，七个角色。保留 Muse 官方形象，另加我们的布比和 5 个 AI 角色，在设置里切换。画风统一对齐 Muse 官方的微像素风格，宠物和游戏也用同一套角色。
  • 一次刷机，之后全部在线升级。第一次用 USB 刷入，之后通过自建 OTA 更新。
  • 开发全程在云端。代码放在 GitHub，Actions 编译，Windows 电脑只负责第一次刷机。

03条款与边界

代码是开源的，但接入 Muse 服务受 SDK token 条款约束。开源许可证不授予任何 token 权利。

事项条款规定结论
使用性质个人、非商业使用自用可以
送人一个 token 最多嵌入 50 台给别人用的设备，最多关联 50 台送朋友可以
售卖（嵌入我们的 token）不能把你的 token 嵌入收费出售、公开上架或用于促销的设备；其他分发需要 Meta 书面许可不能这样卖
售卖（用户自填 token）固件不带任何 token，买家用自己的 token，属于其本人使用。条款没有直接禁止，但 Meta 如何认定不由我们决定灰色地带，售卖前确认
他人数据对方配对前要告知设备如何处理其信息；不得截留或转发其对话需告知
品牌不得暗示设备由 Meta 制造或背书名字不带 Muse
形象版权默认吉祥物 Jollybot 是 Meta 的角色，Apache 协议不覆盖；GPT、Codex、小克、小鲸鱼、豆包取材于各家品牌只限自用，送人或售卖只留布比
绕过 token不得绕过使用限制或安全措施不做
稳定性官方明确说这不是正式产品，随时可能变更或停止商业风险

设计决定：token 由用户自己填。固件不内置任何人的 token。每个用户在 gadgets.muse.ai 生成自己的 token，在设备设置页填入，属于用户本人的使用。这样“嵌入我们的 token 售卖”这条限制不再直接适用，送给朋友时用的也都是对方自己的账号和 token。但条款同时要求个人、非商业使用，不得暗示 Meta 背书，且随时可能修改，所以正式售卖前仍要确认条款或取得 Meta 授权，并且设备只能带布比，不带 Meta 的默认形象和其他品牌角色。

04官方固件能力

固件要求 ESP-IDF v6.0.1，其他版本官方不支持。入口在 main/main.c，主要逻辑在 main/app.c，带屏板子的形象、语音和设置界面在 components/muse。设备通过蓝牙与手机配对，接入 Wi-Fi，与 Muse 云端保持加密会话。

形象动画

默认形象是 64×64 的像素角色，由代码实时绘制（muse_pixel.c），共 8 种状态：开机、待机、聆听、思考、说话、出错、关机，以及被摸时的开心反应。官方脚本 avatar.py 能让你的 Muse 把自己的形象重画成新的绘制代码，还支持一句话修改，比如“耳朵大一点”。

64×64 在 466×466 的屏幕上放大到 320×320，每个像素成 5×5 的方块（读代码确认），所以看起来偏粗糙。这是刻意的复古像素风：不占存储，在 S3 上每帧绘制不到 10 毫秒。Muse 生成的用户形象也是同样规格。

设备命令

设备向 Muse 注册命令，Muse 在对话中调用它们。已有的例子包括 display.draw_url（显示网络图片）、sensors.read（读传感器）、camera.capture（拍照，Seeed Watcher 上）。Boopie 的大部分扩展都会通过新增命令接入 Muse。

06底座与架构

底座选择

以 Muse 固件为底座加功能拆开放进 ESP-Brookesia
Muse 可用时间第一天就能用移植完才能用
跟进官方更新容易合并每次手工搬
工作量小大
App 多了以后结构可能变乱天生为多 App 设计

决定：先以 Muse 固件为底座。我们的代码全部放在独立模块目录里，只在少数几个固定挂钩点改动 Muse 原有代码，比如主界面入口和页面注册。这样官方更新时冲突少；以后应用多到撑不住，也能把模块整体搬进 Brookesia。最终方案在读完界面代码后确认。

双大脑：一个形象，两套 AI 后端 已实现

Muse 的连接是板子直连 Meta 云端的端到端加密会话，我们的服务器插不进去，所以两套后端各走各的链路，统一放在板子上的中间层。

层内容说明
界面层形象动画、状态、按键说话、屏幕、宠物、游戏两个大脑共用
大脑接口开始听、发送音频、收到文字和语音、状态变化、工具调用统一事件
能力清单倒计时、开始游戏、读取姿态、振动等设备功能定义一次，同时导出成 Muse 命令和国内模型的 MCP 工具
Muse 大脑官方客户端，直连 Meta 云端需要 Muse token 和可访问海外的网络
国内大脑小智协议客户端：WebSocket + Opus 音频经小智官方服务器做语音识别、大模型、语音合成，无需代理
  • 国内链路（最后改用小智官方服务器，激活码绑定，零配置；下面是当初的自建方案）：DeepSeek 只处理文字，需要“语音识别 → 大模型 → 语音合成”链路。服务器用开源的 xiaozhi-esp32-server（Docker 部署），支持阿里、腾讯语音识别，通义、豆包及任何 OpenAI 兼容接口，DeepSeek 走兼容接口。服务器放国内机房，延迟低。
  • 小智固件是 MIT 协议，可商用，设备端工具用 MCP 定义，正好对接能力清单。
  • 费用：小智按其官方服务器的规则使用；Muse 用用户自己的 token。
  • 切换：新手引导或 设置 › AI 助手 里选 Muse 或小智，同一时间只运行一个，切换后重启，不占双份内存。
  • IDF 版本：没有合并小智固件，只在 Boopie 组件里实现了小智协议，所以还是 IDF 6.0.1。

底层改造

  1. token 用户自填 已实现：从编译时写死改为存进 NVS，启动时读取。所有人刷同一个固件。（计划里的 NVS 加密最后没开，见“现状”。）长按按键 5 秒重置时一并清除；换 Muse token 后需在 Muse App 重新配对。
  2. 手机设置页 已实现：设备屏幕显示二维码，手机扫码打开设备自带的设置页，粘贴填写 Wi-Fi、大脑选择、Muse token、国内 API key 和代理。几十位的密钥不适合在 1.75 寸圆屏上手敲，屏幕键盘只作兜底（例如 Wi-Fi 密码）。以后有 iOS App，改为在 App 里粘贴、蓝牙写入。
  3. 网络代理 已实现：最后直接做了完整方案：板子上跑 Shadowsocks，手机导入订阅（通用 / V2rayN 或 Clash 格式），只让 Muse 和系统更新的域名走代理，其余直连。

两种联网模式 出门模式未做

Muse 需要连到海外云端。Boopie 同时保留两种联网方式，在家用 Wi-Fi，出门像手表一样靠手机。

在家：Wi-Fi + 代理出门：蓝牙连手机中转
链路板子 → Wi-Fi → 局域网代理 → Muse 云端板子 ⇄ 蓝牙 ⇄ Boopie iOS App ⇄ 手机网络（含 VPN）⇄ Muse 云端
代理板子上配置代理地址或导入节点板子不碰代理，手机怎么联网板子就怎么联网
带宽充足，图片和语音都流畅几十到一两百 KB/s，语音够用，图片偏慢
功耗较高可关 Wi-Fi，更省电
前提局域网有代理，或路由器本身可直连需要自己开发 Boopie iOS App；iOS 后台蓝牙联网稳定性需实测
隐私板子与 Muse 之间端到端加密，代理和 App 只转发字节，看不到对话内容，符合条款中不截留他人数据的要求

官方固件里蓝牙只用于配对，之后板子用 Wi-Fi 直连云端，官方 Muse App 不会帮板子转发流量，所以蓝牙中转需要固件加一层“网络走蓝牙”的转发，加上我们自己的 iOS App。这条蓝牙通道和骑行导航、配套 App 是同一条，一起开发。零开发的备选是让板子连手机热点，但 iOS 热点设备的流量通常不走手机上的 VPN，需要实测。

形象系统：统一 Muse 微像素风格 已实现

原来设想的高清形象、自定义形象包和字符画都已放弃。所有角色对齐 Muse 官方的画法：64×64 网格放大 5 倍成 320 像素，由代码实时绘制，有序抖动做明暗，加状态色光晕、边缘光、环绕的星光和脚下阴影，聆听和说话时外圈有点状圆环，整屏配色跟着状态变。

  • 不需要额外的资源分区，也不做“导入形象包”。角色是代码，不是图片，固件大小基本不变。
  • 换色走调色板：给一个主色，程序算出暗部、亮部、高光、描边和状态灯。设置页有 9 种预设颜色，每个角色单独记住。
  • 更多自定义：设置页的选项，或者让 Muse 生成代码后通过 OTA 更新。

表情规范：13 个表情 + 叠加层 已实现

系统只发出表情编号，由当前角色画出来，所以 AI、宠物、游戏触发的表情在任何角色下都一致。前 7 个顺序与官方状态相同。

类别内容说明
核心 8 个开机、待机、聆听、思考、说话、出错、关机、开心（被戳）覆盖官方固件全部状态，每个角色必须画。思考持续几秒后变成“工作中”：掏出小笔记本敲键盘
宠物 5 个饿了 → 待机，吃东西 → 开心，犯困 → 关机，难过 → 待机，晕了 → 出错箭头后是角色没画时的退回表情。宠物表情只在待机时显示
叠加层·反应“!” 惊讶、大腮红（害羞）、彩色纸屑（庆祝）、飘爱心不算表情，盖在任何表情上，可以同时开几个
叠加层·设备低电量（红色空电池闪烁）、充电中（闪电和上升的光点）由电量自动触发：充电时、电量 ≤15% 时
  • 退回规则：某个角色还没画某个宠物表情时，自动显示退回的核心表情，新增表情不会让任何角色坏掉。Muse 官方角色目前就是这样显示宠物表情的，后续补画。
  • 切换与命令：设置页新增“Avatar”，选角色和颜色，重启后保留。远程命令 display.avatar 可以换角色、换颜色、设宠物表情、开关反应叠加层。
  • 验证方式：Python 原型 tools/boopie/avatar_proto.py 是设计稿，固件里的 C 代码逐行移植，测试让两边画同一帧逐像素比较；模拟器里截图每个角色的每种状态。

自建 OTA

提交代码→GitHub Actions 编译→自有密钥签名→上传 Cloudflare R2→Worker 版本清单→设备后台下载、切换、重启
  • 已实现 更新源是自己的服务器 boopie-ota.wenjinuu.workers.dev；Muse 官方推送的升级（蓝牙、配网、控制通道）一律拒收。
  • 发布流程用只存在 GitHub Secrets 里的 P-256 私钥给更新清单签名，板子用编进固件的公钥验签，再逐个校验文件的 SHA-256。
  • 启动失败自动回滚：新固件界面正常跑 45 秒且 Wi-Fi 连上才算装好，否则退回旧程序区。
  • 每次发布都有正常版和解锁版两种，板子跟着自己那种更新，也能在设置里切换。
  • 资源包（字体、美术）一起更新：先下载到用户数据区，下次启动时再写进资源区。
  • 固件放 R2，国内下载也快；VPN 开着时走 VPN。细节见 OTA 设计。

小游戏设计

决定性能的不是画风，而是每帧有多少像素在变。S3 没有图形加速，466×466 全屏一帧约 434 KB，每帧整屏重画会很吃力；只重画移动的小区域就很轻松。像素风的优势在于可以用低分辨率画、再放大显示，全屏都在动的游戏用它最稳。所以策略是：

  • 背景静态、角色和道具小而动：只刷新变化的区域，背景可以是高清的。
  • 全屏动作类用像素风：按 1/4 分辨率绘制再放大，计算量降到约 1/16。
  • 游戏和主界面用同一个像素布比：64×64 的角色本来就是按像素风画的，直接当游戏角色。
  • 黑底为主：AMOLED 黑色像素不发光，省电，也减少要画的内容。
  • 目标 30 帧，AI 说话时游戏自动暂停。
游戏玩法用到渲染压力
戳戳布比 首批布比在圆屏边缘随机冒头，限时点中得分触摸很低
布比接零食 首批倾斜板子让布比沿底部圆弧移动，接住掉下的零食，喂给宠物陀螺仪低
吹气飞飞对着麦克风吹气或喊，声音越大布比飞得越高，躲开障碍麦克风中
圆环躲避圆环障碍向中心收缩，旋转板子找缺口，专为圆屏设计陀螺仪 / 触摸中，用像素风

已确定首批两款：先做“戳戳布比”，打通触摸、角色绘制、计分和奖励宠物这一整套机制；再做“布比接零食”，把陀螺仪用起来。两款游戏挣到的零食和心情都直接反馈给宠物主界面。“吹气飞飞”和“圆环躲避”留作后续。

同类开源项目可参考：乐鑫 ESP-Brookesia（手机式启动器）、基于它的微雪 S3-Watch 手表固件、Tactility（ESP32 小系统，GPL-3 协议）。

09风险与处理结果

事项影响应对
国内网络设备连不上 Muse 云端，一切停摆已解决 确实连不上，做了板载 Shadowsocks VPN；不想折腾的用小智
密钥安全token 存在板子上，可能被读出接受 为了能反复刷机没开 NVS 加密；只经加密连接发送，日志不打印；丢了板子就去官网吊销。OTA 签名私钥只在 GitHub Secrets
IDF 版本合并小智要 6.0.2+，Muse 锁 6.0.1已解决 不合并固件，只在 Boopie 组件里实现小智协议
蓝牙中转带宽有限；iOS 后台蓝牙联网可能被系统挂起只承担语音和小数据；在家优先走 Wi-Fi；做原型实测
官方随时变更SDK 不是正式产品，可能改动或停止保持上游同步；宠物、表盘等功能不依赖 Muse
内存微雪只有 8 MB PSRAM，多应用同跑可能吃紧已处理 确实碰到过卡死和崩溃：字体和美术移到资源区按需读、去掉图层效果、短任务栈放 PSRAM、蓝牙按需启动
S31 支持IDF 6.1 对 S31 仍是预览Mosaico 放在阶段 5，等主线稳定
官方 OTA 覆盖自改固件可能被官方更新替换已解决 拒收官方推送的升级，只装自己签名的版本
界面代码结构若写得很死，挂钩点难找已解决 改动集中在少数挂钩点，标 Boopie:，见代码摸底说明
商业化与版权条款禁止售卖嵌入我们 token 的设备；用户自填 token 属灰色地带；品牌角色和主题皮肤有版权当前只做自用与送人，代码已按 Apache 2.0 开源；品牌角色、主题皮肤和 Jollybot 不在开源范围内，见 开源协议与第三方
形象绘制耗时角色每帧实时绘制待实测 已在真机上运行，单帧耗时还没单独测量；预算是 40 毫秒一帧
