设计方案 · v0.1 · 2026-10-03

Boopie布比

一块圆屏小设备上的多应用系统。Muse 是常驻的 AI 应用，旁边再装电子宠物、表盘、信息卡片和小游戏。名字来自 boop，戳它一下，它就会有反应。

仓库 wenjinliuu/boopie-firmware Secret MUSE_SDK_TOKEN 主板 微雪 ESP32-S3-Touch-AMOLED-1.75C 第二板 乐鑫 ESP-Mosaico

01项目概述

Meta 在 2026 年 10 月 2 日开源了 Muse Gadgets：一套 ESP32 固件和 Linux SDK，让现成的开发板变成 Muse 的外设。Boopie 以这套固件为起点，扩展成一个通用的圆屏小系统。

核心定位

  • Muse 是一个应用，不是全部。它常驻在系统里，按键就能对话；其他时间屏幕交给宠物、表盘和各类小应用。
  • 主角是你自己的 Muse 形象。每个用户的 Muse 都能生成专属像素形象，Boopie 的宠物和游戏都用它当角色，不使用 Meta 的默认吉祥物。
  • 一次刷机，之后全部在线升级。第一次用 USB 刷入，之后通过自建 OTA 更新。
  • 开发全程在云端。代码放在 GitHub，Actions 编译，Windows 电脑只负责第一次刷机。

03条款与边界

代码是开源的，但接入 Muse 服务受 SDK token 条款约束。开源许可证不授予任何 token 权利。

事项条款规定结论
使用性质个人、非商业使用自用可以
送人一个 token 最多嵌入 50 台给别人用的设备，最多关联 50 台送朋友可以
售卖（嵌入我们的 token）不能把你的 token 嵌入收费出售、公开上架或用于促销的设备；其他分发需要 Meta 书面许可不能这样卖
售卖（用户自填 token）固件不带任何 token，买家用自己的 token，属于其本人使用。条款没有直接禁止，但 Meta 如何认定不由我们决定灰色地带，售卖前确认
他人数据对方配对前要告知设备如何处理其信息；不得截留或转发其对话需告知
品牌不得暗示设备由 Meta 制造或背书名字不带 Muse
默认形象默认吉祥物 Jollybot 是 Meta 的角色，Apache 协议不覆盖用自己的形象
绕过 token不得绕过使用限制或安全措施不做
稳定性官方明确说这不是正式产品，随时可能变更或停止商业风险

设计决定：token 由用户自己填。固件不内置任何人的 token。每个用户在 gadgets.muse.ai 生成自己的 token，在设备设置页填入，属于用户本人的使用。这样“嵌入我们的 token 售卖”这条限制不再直接适用，送给朋友时用的也都是对方自己的账号和 token。但条款同时要求个人、非商业使用，不得暗示 Meta 背书，且随时可能修改，所以正式售卖前仍要确认条款或取得 Meta 授权，并且设备不能带 Meta 的默认形象。

04官方固件能力

固件要求 ESP-IDF v6.0.1，其他版本官方不支持。入口在 main/main.c，主要逻辑在 main/app.c，带屏板子的形象、语音和设置界面在 components/muse。设备通过蓝牙与手机配对，接入 Wi-Fi，与 Muse 云端保持加密会话。

形象动画

默认形象是 64×64 的像素角色，由代码实时绘制（muse_pixel.c），共 8 种状态：开机、待机、聆听、思考、说话、出错、关机，以及被摸时的开心反应。官方脚本 avatar.py 能让你的 Muse 把自己的形象重画成新的绘制代码，还支持一句话修改，比如“耳朵大一点”。

64×64 在 466×466 的屏幕上放大到 320×320，每个像素成 5×5 的方块（读代码确认），所以看起来偏粗糙。这是刻意的复古像素风：不占存储，在 S3 上每帧绘制不到 10 毫秒。Muse 生成的用户形象也是同样规格。

设备命令

设备向 Muse 注册命令，Muse 在对话中调用它们。已有的例子包括 display.draw_url（显示网络图片）、sensors.read（读传感器）、camera.capture（拍照，Seeed Watcher 上）。Boopie 的大部分扩展都会通过新增命令接入 Muse。

06底座与架构

底座选择

以 Muse 固件为底座加功能拆开放进 ESP-Brookesia
Muse 可用时间第一天就能用移植完才能用
跟进官方更新容易合并每次手工搬
工作量小大
App 多了以后结构可能变乱天生为多 App 设计

决定：先以 Muse 固件为底座。我们的代码全部放在独立模块目录里，只在少数几个固定挂钩点改动 Muse 原有代码，比如主界面入口和页面注册。这样官方更新时冲突少；以后应用多到撑不住，也能把模块整体搬进 Brookesia。最终方案在读完界面代码后确认。

双大脑：一个形象，两套 AI 后端（优先推进）

Muse 的连接是板子直连 Meta 云端的端到端加密会话，我们的服务器插不进去，所以两套后端各走各的链路，统一放在板子上的中间层。

层内容说明
界面层形象动画、状态、按键说话、屏幕、宠物、游戏两个大脑共用
大脑接口开始听、发送音频、收到文字和语音、状态变化、工具调用统一事件
能力清单倒计时、开始游戏、读取姿态、振动等设备功能定义一次，同时导出成 Muse 命令和国内模型的 MCP 工具
Muse 大脑官方客户端，直连 Meta 云端需要 Muse token 和可访问海外的网络
国内大脑小智协议客户端：WebSocket + Opus 音频经国内服务器调用语音识别、大模型、语音合成，无需代理
  • 国内链路：DeepSeek 只处理文字，需要“语音识别 → 大模型 → 语音合成”链路。服务器用开源的 xiaozhi-esp32-server（Docker 部署），支持阿里、腾讯语音识别，通义、豆包及任何 OpenAI 兼容接口，DeepSeek 走兼容接口。服务器放国内机房，延迟低。
  • 小智固件是 MIT 协议，可商用，设备端工具用 MCP 定义，正好对接能力清单。
  • 费用：用户填自己的 API key，和 Muse token 同一个道理，在同一个设置流程里完成。
  • 切换：设置页选“Muse”或“国内 AI”，同一时间只运行一个，不占双份内存。
  • 待验证：小智要求 IDF 6.0.2 及以后的 6.0 版本，Muse 固件是 6.0.1，合并时统一到 6.0.x。

底层改造

  1. token 与 API key 用户自填：从编译时写死改为存进 NVS，启动时读取。所有人刷同一个固件。打开 NVS 加密，防止拿到板子的人直接读出。长按按键 5 秒重置时一并清除；换 Muse token 后需在 Muse App 重新配对。
  2. 扫码设置：设备屏幕显示二维码，手机扫码打开设备自带的设置页，粘贴填写 Wi-Fi、大脑选择、Muse token、国内 API key 和代理。几十位的密钥不适合在 1.75 寸圆屏上手敲，屏幕键盘只作兜底（例如 Wi-Fi 密码）。以后有 iOS App，改为在 App 里粘贴、蓝牙写入。
  3. 可配置网络代理：先做轻量方案，设备连接经局域网代理（例如开了“允许局域网”的 Clash）转发；导入节点、在板子上直接跑代理协议的完整方案作为研究方向。

两种联网模式

Muse 需要连到海外云端。Boopie 同时保留两种联网方式，在家用 Wi-Fi，出门像手表一样靠手机。

在家：Wi-Fi + 代理出门：蓝牙连手机中转
链路板子 → Wi-Fi → 局域网代理 → Muse 云端板子 ⇄ 蓝牙 ⇄ Boopie iOS App ⇄ 手机网络（含 VPN）⇄ Muse 云端
代理板子上配置代理地址或导入节点板子不碰代理，手机怎么联网板子就怎么联网
带宽充足，图片和语音都流畅几十到一两百 KB/s，语音够用，图片偏慢
功耗较高可关 Wi-Fi，更省电
前提局域网有代理，或路由器本身可直连需要自己开发 Boopie iOS App；iOS 后台蓝牙联网稳定性需实测
隐私板子与 Muse 之间端到端加密，代理和 App 只转发字节，看不到对话内容，符合条款中不截留他人数据的要求

官方固件里蓝牙只用于配对，之后板子用 Wi-Fi 直连云端，官方 Muse App 不会帮板子转发流量，所以蓝牙中转需要固件加一层“网络走蓝牙”的转发，加上我们自己的 iOS App。这条蓝牙通道和骑行导航、配套 App 是同一条，一起开发。零开发的备选是让板子连手机热点，但 iOS 热点设备的流量通常不走手机上的 VPN，需要实测。

形象系统：四种风格

档位内容说明
像素风保留官方 64×64 绘制机制，用户可让自己的 Muse 生成像素形象官方路线
Boopie 高清默认我们自己设计的高清角色（粉色布比），作为出厂默认替代 Meta 的 Jollybot，送人或售卖的设备都不带 Meta 角色
自定义高清形象包用户用 AI 生图做出各状态角色图，云端工具转成形象包，经 OTA 推到设备每个人的布比都独一无二
字符画布比由字母、数字、标点按明暗排列拼成，说话时字符跳动闪烁；开机时乱码收拢成布比灵感来自 Muse 官网首页的字符画手法。只画文字，不存图片，S3 很轻松；黑底亮字在 AMOLED 上效果好。拼的是布比，不照搬 Muse 标志

高清实现有两条路线，到货后实测再定：

  • 序列帧：每个状态一组图片轮播，效果最好。8 种状态每种十几帧，不压缩会超过 10 MB，需要压缩或降低帧率；32 MB Flash 装得下。
  • Lottie 矢量动画：LVGL 9 支持，文件小、缩放清晰，可从 AE 等工具导出；渲染吃算力，大尺寸下帧率要实测。

表情规范：所有风格统一

四种风格共用一套表情清单和编号。系统只发出表情编号，由当前风格负责画出来，这样双大脑、宠物、游戏触发的表情在任何风格下都一致。

  • 退回规则：某种风格还没做某个扩展表情时，自动显示“缺省时退回”那一列的表情，所以新增表情不会让任何风格坏掉。
  • 像素风的限制：Muse 生成的像素形象只包含 8 个核心表情。扩展表情要么用退回规则，要么在生成提示词里追加这些状态，让 Muse 一起画出来。
  • 新增表情的流程：先在清单里加编号和退回目标，再逐个风格补画，补完一个上线一个。

自建 OTA

提交代码→GitHub Actions 编译→自有密钥签名→上传 Cloudflare R2→Worker 版本清单→设备后台下载、切换、重启
  • 更新源指向我们自己的服务器，避免被官方 OTA 覆盖。自编译固件版本号默认 999.0.0，具体判断逻辑待读代码确认。
  • 官方仓库用公开的开发密钥签名，我们换成自己的私钥，设备只接受我们签名的固件。
  • 打开 ESP-IDF 的启动失败自动回滚，升级出错退回旧槽。
  • 固件放 R2，同时解决国内下载 GitHub 慢的问题。

07应用规划

三大基础（同步重要）

① Muse 对话

第一位。先把 Muse 接通落地：按键说话、语音回复、显示 Muse 推来的图片。

② 国内大脑

小智协议接 DeepSeek、通义、豆包等国内模型，国内网络直连，不用代理。形象和宠物与 Muse 共用。

布比就是主界面。平时陪着你，有心情、饥饿、成长；按键时就是 AI 在说话。表盘时间也显示在这一屏。

小游戏设计

决定性能的不是画风，而是每帧有多少像素在变。S3 没有图形加速，466×466 全屏一帧约 434 KB，每帧整屏重画会很吃力；只重画移动的小区域就很轻松。像素风的优势在于可以用低分辨率画、再放大显示，全屏都在动的游戏用它最稳。所以策略是：

  • 背景静态、角色和道具小而动：只刷新变化的区域，背景可以是高清的。
  • 全屏动作类用像素风：按 1/4 分辨率绘制再放大，计算量降到约 1/16。
  • 游戏里用像素版布比：官方 64×64 像素形象天然适合当游戏角色，主界面再用高清版。
  • 黑底为主：AMOLED 黑色像素不发光，省电，也减少要画的内容。
  • 目标 30 帧，AI 说话时游戏自动暂停。
游戏玩法用到渲染压力
戳戳布比 首批布比在圆屏边缘随机冒头，限时点中得分触摸很低
布比接零食 首批倾斜板子让布比沿底部圆弧移动，接住掉下的零食，喂给宠物陀螺仪低
吹气飞飞对着麦克风吹气或喊，声音越大布比飞得越高，躲开障碍麦克风中
圆环躲避圆环障碍向中心收缩，旋转板子找缺口，专为圆屏设计陀螺仪 / 触摸中，用像素风

已确定首批两款：先做“戳戳布比”，打通触摸、角色绘制、计分和奖励宠物这一整套机制；再做“布比接零食”，把陀螺仪用起来。两款游戏挣到的零食和心情都直接反馈给宠物主界面。“吹气飞飞”和“圆环躲避”留作后续。

同类开源项目可参考：乐鑫 ESP-Brookesia（手机式启动器）、基于它的微雪 S3-Watch 手表固件、Tactility（ESP32 小系统，GPL-3 协议）。

08阶段路线

  1. 0

    云端编译跑通 现在开始

    • 把官方仓库导入 boopie-firmware，保留官方仓库作为上游
    • GitHub Actions 用官方 IDF 6.0.1 环境编译微雪 1.75C 配置
    • token 存 GitHub Secrets，名称固定为 MUSE_SDK_TOKEN，编译时注入 CONFIG_GADGET_SDK_TOKEN
    • 摸清代码：界面组织、OTA 来源、token 使用位置、命令注册方式

    产出：可下载的 .bin 固件和一份代码摸底说明。你要做：在 gadgets.muse.ai 生成 token，存入仓库 Settings › Secrets and variables › Actions，名称 MUSE_SDK_TOKEN。token 不进代码、不发聊天。

  2. 1

    到货刷机，Muse 对话落地 基础 ①

    • Windows 上先备份原厂固件，再用网页刷机工具刷入
    • Muse App 配对，验证国内网络能否连上，跑通按键对话
    • 手动生成自己的形象：在 Muse App 发提示词，拿到代码交给云端编译

    产出：能和 Muse 对话、显示自己形象的板子。

  3. 2

    底座改造

    • token 用户自填，配网设置页，可配置代理
    • 自建 OTA、自有签名密钥、自动回滚
    • 页面切换框架，代码放独立模块

    产出：此后升级不再需要插电脑。

  4. 3

    双大脑与宠物主界面 基础 ② ③

    • 抽出大脑接口，接入国内大脑（小智协议 + 自部署服务器 + 用户自己的 API key）
    • 建立能力清单，同时导出成 Muse 命令和 MCP 工具
    • 电子宠物作为主界面：心情、饥饿、成长，时间显示在同一屏

    产出：三大基础齐备：不用代理也能完整使用，布比就是主界面，两个大脑都能调用板子功能。

  5. 4

    小游戏

    • 先做“戳戳布比”，打通触摸、角色、计分、奖励宠物
    • 再做“布比接零食”，用上陀螺仪
    • 注册“开始游戏”命令，让 AI 能直接启动游戏

    产出：能玩、能喂宠物、能被 AI 叫起来的小游戏。

  6. 5

    移植 Mosaico

    • 备份原厂固件，升级 IDF 6.1，新建板子配置，适配方屏和触摸
    • 加入摄像头命令；S31 有 2D 图形加速，游戏和高清形象会更流畅

    产出：两块板子跑同一套 Boopie。

  7. 6

    扩展（按兴趣挑）

    • iOS 配套 App：蓝牙中转联网（出门模式）、骑行导航，共用一条蓝牙通道
    • 信息卡片、更多小游戏

09风险与待确认

事项影响应对
国内网络设备连不上 Muse 云端，一切停摆阶段 1 首先验证；连不上就把代理功能提前
密钥安全token 和 API key 存在板子上，可能被读出打开 NVS 加密；只通过加密连接发送；可随时在官网或服务商处吊销
IDF 版本合并小智要 6.0.2+，Muse 锁 6.0.1统一到 6.0.x 后跑通两套客户端再合并
蓝牙中转带宽有限；iOS 后台蓝牙联网可能被系统挂起只承担语音和小数据；在家优先走 Wi-Fi；做原型实测
官方随时变更SDK 不是正式产品，可能改动或停止保持上游同步；宠物、表盘等功能不依赖 Muse
内存微雪只有 8 MB PSRAM，多应用同跑可能吃紧应用按需加载，阶段 2 实测
S31 支持IDF 6.1 对 S31 仍是预览Mosaico 放在阶段 5，等主线稳定
官方 OTA 覆盖自改固件可能被官方更新替换读代码确认，更新源指向自建服务器
界面代码结构若写得很死，挂钩点难找阶段 0 读代码后再定方案
商业化条款禁止售卖嵌入我们 token 的设备；用户自填 token 属灰色地带当前只做自用与送人；售卖前确认条款或取得授权；设备不带 Meta 默认形象
高清形象性能序列帧占存储，Lottie 占算力到货后两种路线各做一个状态实测帧率和体积
